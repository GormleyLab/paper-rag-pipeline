## Problem Summary

An MCP (Model Context Protocol) server deployed to AWS Bedrock AgentCore returns internal errors on invocation. The container appears to never start - no logs are generated despite multiple deployment attempts and invocations.

**Key Observation:** The JSON-RPC error response contains a **different ID** than the request, indicating the error is generated by AgentCore's proxy infrastructure, not by the MCP server itself.

## Troubleshooting Steps Taken

### 1. Port Configuration
- **Issue:** Initially configured for port 8000
- **Fix:** Changed to port 8080 (discovered AgentCore expects 8080 from SDK source code)
- **Result:** No change in behavior

### 2. Security Group Rules
- **Issue:** No inbound rules initially
- **Fix:** Added inbound rules for port 8080:
  - From self-referencing security group
  - From VPC CIDR (10.0.0.0/16)
- **Result:** No change in behavior

### 3. Environment Variables
- **Issue:** Dockerfile regeneration removed required env vars (DATABASE_URL, OPENAI_API_KEY, S3_BUCKET)
- **Fix:** Manually added environment variables to Dockerfile
- **Result:** No change in behavior

### 4. OpenTelemetry Instrumentation
- **Issue:** Suspected otel wrapper might cause issues
- **Fix:** Changed CMD from `opentelemetry-instrument python -m ...` to `python -m ...`
- **Result:** No change in behavior

### 5. RDS Connectivity
- **Verified:** RDS security group (sg-06ab99e7a43408486) allows inbound on port 5432 from AgentCore security group (sg-0c30f1d1fd79b9df2)

### 6. Module Invocation vs Direct Execution
- **Issue:** MCP server is in `src/mcp_http_server.py` (subdirectory), not project root as shown in AWS documentation
- **Observation:** AWS docs show `mcp_server.py` at project root, not nested
- **Fix Attempted:** Changed CMD from `python -m src.mcp_http_server` to `python src/mcp_http_server.py`
- **Result:** No change in behavior

### 7. Root-Level MCP Server Wrapper
- **Issue:** AWS documentation shows MCP server at project root
- **Fix:** Created `mcp_server.py` at project root that imports and runs `src.mcp_http_server`
- **Verified:** Wrapper works correctly locally (returns all 10 tools)
- **Result:** No change in behavior when deployed

### 8. Debug Output for Container Startup
- **Issue:** Need to verify if container even starts
- **Fix:** Added print statements at very start of `mcp_server.py`:
  - `"=== MCP SERVER STARTING ==="` on first line
  - Python version and executable info
  - Import status
- **Result:** **No debug output ever appears in logs** - confirms container never starts

### 9. Multiple Redeployments (8+ deployments)
- Deployed 8+ times with various configuration changes
- CodeBuild succeeds every time
- Container image pushed successfully to ECR
- Runtime status always shows READY
- **Zero logs generated in any deployment**

## Conclusion

**The MCP server code is verified to work correctly locally.** The issue is definitively in the AgentCore infrastructure:

1. **Container never starts** - Debug print statements at the very first line of execution never appear in logs
2. **No logs generated** - `runtime-logs` stream never created, `otel-rt-logs` has 0 bytes
3. **Error ID mismatch** - JSON-RPC error response has different ID than request, proving error originates from AgentCore proxy
4. **Build succeeds** - CodeBuild successfully builds ARM64 image and pushes to ECR
5. **Status shows READY** - Agent runtime and endpoint both report ready status

This appears to be an issue with AgentCore's container orchestration failing to start the container, or the container crashing before any Python code executes.
